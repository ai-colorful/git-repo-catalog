## 2. 项目是什么，解决什么问题

funNLP 不是软件库，而是一个"内容型仓库"：主体由两部分构成——一份 1056 行、约 138KB 的 `README.md` 链接索引，和一个 161MB 的 `data/` 词库语料目录。作者（知乎 ID mountain-blue-64，主页 https://zhuanlan.zhihu.com/yangyangfuture，见仓库 homepage 字段）在 2018 年前后从入门到熟悉 NLP 的过程中收集了大量 GitHub 资源，遂整理成清单分享（`README.md` 开篇自述"用到了很多github上的包，遂整理了一下，分享在这里"）。

它解决的问题非常实际：2018 年前后中文 NLP 的工具、词库、语料散落在各处且质量参差，中文开发者缺少一个统一的入口。funNLP 把敏感词过滤、人名/公司名语料、停用词、繁简转换、预训练模型、知识图谱、对话系统等几十个方向的资源按任务类型归档，每个条目附带一句话描述和跳转链接，让人"按任务找资源"而非"按项目名搜 GitHub"。

`data/` 目录则更进一步：不仅是索引，还直接托管了一批高频使用的词库本体，如 120 万条中文人名（含性别标注）、48 万条中英对照名、480 万条公司名（RAR 压缩包）、5 万条成语、33MB 的微博谣言 JSON 数据、THUOCL 系列（IT/医学/法律/财经等）领域词库。这些数据在分词、NER、信息抽取等工程场景中被大量直接引用。

2023 年起 README 新增了 11 个 LLM 相关分类（"类ChatGPT的模型评测对比""LLM的训练_推理_低资源_高效训练""提示工程""多模态LLM"等，`README.md` 第 128-339 行），说明作者在 ChatGPT 浪潮后仍试图把索引范围延伸到大模型时代，但 2023-08 之后实质更新基本停止。

## 3. 技术栈与依赖

作为内容型仓库，没有软件意义上的技术栈：

- **语言标注**：GitHub 元数据标注主语言为 Python，来源是仓库内唯一的代码文件 `data/中文分词词库整理/thirtyw.py`——一个 Python 2 语法的词库清洗脚本（`print temp_sublist[1]`，无括号），用于从 30 万分词词库中提取词项。
- **数据格式**：绝大多数资源为纯文本 `.txt`（每行一词/一名）、JSON（`data/中文谣言数据/rumors_v170613.json`，每行一条谣言，含 rumorCode/title/informerName 等字段）、XLSX（`data/中英日文名字库/Chinese_Names_Corpus/Chinese_Relationship（4.8k）.xlsx`）、RAR/ZIP 压缩包（`data/公司名字词库/Company-Names-Corpus（480W）.rar`）以及少量 PDF（`data/NLP_BOOK/eisenstein-nlp-notes.pdf`、`data/paper/LLM_Survey_Chinese_0418.pdf`）。
- **无任何依赖清单**：不存在 requirements.txt / pyproject.toml / package.json，无构建系统。

## 4. 目录结构与代码组织

顶层只有三项（解压后 `ls` 确认）：

| 目录/文件 | 职责 |
| :--- | :--- |
| `README.md` | 核心内容：1056 行、51 个一级分类、597 条 https 链接的资源索引 |

`data/` 子目录按词库主题平铺命名，主要包括：`中英日文名字库`（人名三大库）、`中文分词词库整理`（多个 30 万级通用词库）、`公司名字词库`、`中文谣言数据`、`成语词库`、`同义词库、反义词库、否定词库`、`停用词`、`拆字词库`、`繁简体转换词库`、`医学词库`、`法律词库`、`财经词库`、`IT词库`、`古诗词库`、`历史名人词库`、`地名词库`、`汽车品牌、零件词库`、`职业词库`、`食物词库`、`动物词库`、`中文缩写库`、`NLP_BOOK`、`paper`、`.logo图片` 等。

组织方式评述：这是一个"单文件 README + 数据附件"的极简结构，没有模块化、没有版本化（无 tag/release）。README 中只有 2 处直接引用本地 `data/` 路径（如"汽车品牌、汽车零件相关词汇 → data"，`README.md` 词库及词法工具表），其余条目全部指向外部 GitHub 仓库、网盘（百度网盘+提取码）或 arXiv 论文。数据文件普遍以"By@萌名NameMoe + 日期"等来源署名行开头，无统一 README 说明（例外：`data/中文谣言数据/README.md` 承袭自 THUNLP 原仓库）。

## 5. 核心架构与关键实现

内容型仓库的"核心实现"即 README 的组织结构与 data 的数据组织，分别深入如下。

**（1）README 分类体系（`README.md`）**。51 个一级分类按两层组织：第一层是 2023 年新增的 11 个 LLM 分类（类ChatGPT 系列、提示工程、LLM 安全、多模态 LLM、LLM 数据集）；第二层是约 40 个传统 NLP 任务分类——语料库、词库及词法工具、预训练语言模型&大模型、抽取、知识图谱、文本生成/摘要、智能问答、文本纠错、语音处理、文档/表格处理、文本匹配/增强/检索、阅读理解、情感分析、事件抽取、机器翻译、数字转换、指代消解、聚类/分类、知识推理、可解释 NLP、文本攻击、可视化、标注工具、语言检测、综合工具、有趣搞笑工具、课程面试、比赛、金融/医疗/法律 NLP、文本生成图像、其他。分类基本对齐 NLP 任务谱系，是中文社区被引用最广的任务分类法之一。

**（2）条目格式（`README.md` 各分类表）**。统一采用三列表格：`资源名 | 描述 | 链接`。链接形态多样：外部 GitHub 仓库（占绝大多数）、百度网盘（如"中文问答数据集，提取码 2dva"，语料库表）、arXiv（如 arxiv.org/abs/2004.14257 礼貌迁移）、微信公众号文章、以及指向本仓库 `data/` 的相对资源。部分链接已出现格式损坏（如 `http//hlt.suda.edu.cn`、`gistgithub.com`、`quantumstatcom` 缺少标点，README 第 363、378、394 行附近），是长期手工维护未校验的痕迹。

**（3）data/ 词库组织（`data/`）**。文本量约 635 万行（对 data 下 txt/csv 逐文件 `wc -l` 汇总）。代表性数据及其格式：
- `data/中英日文名字库/Chinese_Names_Corpus/Chinese_Names_Corpus_Gender（120W）.txt`：114 万行，格式为 `姓名,性别` 的 CSV（首行 `dict,sex` 表头，抽样见"阿安,男"）；
- `data/公司名字词库/Company-Shorter-Form（28W）.txt`：26.7 万行公司简称，每行一词；480 万全量公司名打包为 `Company-Names-Corpus（480W）.rar`（25MB，GitHub 内直接托管压缩包）；
- `data/成语词库/ChengYu_Corpus（5W）.txt`：5 万成语，每行一条；
- `data/中文谣言数据/rumors_v170613.json`：33MB、微博谣言 JSON Lines 数据（每行含 rumorCode、title、informerName 等字段），承袭自 thunlp/Chinese_Rumor_Dataset；
- `data/医学词库/THUOCL_medical.txt`、`data/法律词库/THUOCL_law.txt` 等：清华大学 THUOCL 开放词库的镜像。
- 唯一代码 `data/中文分词词库整理/thirtyw.py`：约 14 行的 Python 2 脚本，把 `30wChinsesSeqDic.txt` 按词频条件清洗追加到 `30wdict.txt`，无函数无测试，属一次性数据处理痕迹而非工程代码。

**（4）更新方式的"实现"**。没有任何自动化：无 CI（`.github/` 下无 workflows）、无脚本校验链接、无 issue/PR 模板。内容更新依赖作者手工编辑 README 与社区 PR（gh api 显示最后一次合并为 2023-08-24 的 PR #97）。

## 6. 构建与运行

无构建、无安装、无运行概念——这是资源集合而非软件。实际使用方式有两种：

1. **查阅索引**：直接在 GitHub 网页浏览 `README.md`，按分类跳转到各资源原始仓库。
2. **取用词库**：`git clone` 或直接下载 `data/` 下具体文件，用于分词、NER 词典注入、敏感词过滤等；部分大文件（如 480 万公司名）需解压 RAR。注意仓库无许可证声明，商用需自行确认各数据来源的授权（详见第 9 章）。

## 7. 收录规模与分类体系

- **条目规模**：README 共 597 条 https 链接（`grep -c "https://"` 实测），覆盖 51 个分类；其中外部 GitHub 仓库链接约占九成，其余为网盘、论文、公众号与本地 data 引用。
- **收录标准**：无明文收录标准（无 CONTRIBUTING 文件），从条目构成看以"中文可用/中文相关"为隐性主线，兼收英文通用工具（如 huggingface/tokenizers、OpenNMT/Tokenizer）；既有 thunlp、CLUEbenchmark 等学术系资源，也有汪峰歌词生成器、"有趣搞笑工具"等娱乐向条目，宽进宽出。
- **数据体量**：`data/` 33 个子目录、109 个文件，文本词库合计约 635 万行，最大单体 33MB 谣言数据与 25MB 公司名 RAR。数据规模在同类 awesome 索引仓库中罕见，是它区别于纯清单项目的关键。
- **生态位**：与 `AobingCpp/JavaFamily` 式技术路线图、`awesome-*` 纯链接清单不同，funNLP 定位是"中文 NLP 工具+词库+语料"三合一入口；作者自有的 cocoNLP（信息抽取工具，fighting41love 名下，README 词库及词法工具表收录）等姊妹项目通过该索引获得导流。

## 8. 更新机制与维护状态

- **更新机制**：纯手工。作者直接编辑 README，社区通过 PR 补充（gh api commits 显示 2023-08-24 合并 PR #97、2023-06-03 "update multiple LLM frameworks" 等提交均为 README 更新）。无链接有效性检查、无数据版本号、无 CHANGELOG。
- **活跃度曲线**：2018-08 创建后随中文 NLP 热潮快速增长（8.4 万星、1.5 万 fork 的量级主要在 2019-2022 积累）；2023 年上半年集中补入 LLM 分类（commits 记录 2023-05 至 2023-08 密集更新）；**master 分支最后提交 2023-08-24，gh api `pushed_at` 为 2024-05-10，此后至今（2026-10）无任何更新，维护已实质停滞**。
- **社区结构**：11 名 contributors，主体是作者单人维护（符合个人收藏型仓库特征）；55 个 open issues 无人处理；1627 watch。

## 9. 亮点与风险

**亮点**
1. 中文 NLP 资源索引事实上的行业标准之一，8.4 万星与 1.5 万 fork 是社区长期用脚投票的结果（gh api）。
2. "索引 + 本体数据"双形态：不止给链接，还直接托管 635 万行高频词库（`data/`），开箱即用。
3. 分类体系完整且持续演进到 LLM 时代（`README.md` 11 个类 ChatGPT 分类），具备检索价值。
4. 单文件入口零依赖，任何水平的开发者都能直接使用。
5. 作者生态联动（cocoNLP、知乎专栏、FUNDING.yml 捐赠渠道 `.github/FUNDING.yml`）形成了个人品牌闭环。

**风险/局限**
1. **维护停滞**：master 最后提交 2023-08-24（gh api），LLM 分类停留在 2023 年中的认知水平，Agent/RAG/推理模型等 2023 下半年后的方向完全缺失；597 条链接中已实测发现多处格式损坏（README 第 363、378 行附近），死链会继续累积。
2. **无许可证**：仓库无 LICENSE（gh api license=null），`data/` 中大量第三方词库（THUOCL、thunlp 谣言数据等）授权状态不一，直接商用存在合规风险。
3. **数据质量无保障**：词库文件开头带"By@萌名NameMoe"等来源署名行、`Company-Names-Corpus（480W）.rar` 以压缩包托管无法在线预览、部分 txt 存在编码混杂（BOM 头、GBK/UTF-8 混用迹象），使用前需自行清洗。
4. **单人维护、无自动化**：11 名贡献者中更新集中于作者，PR 质量与响应均无流程保障（55 个 open issues 积压）。

## 10. 总结评价

funNLP 是中文 NLP 社区在 2018-2022 年间最重要的一站式资源入口，其价值不在代码而在"整理"——用一份 51 分类、近 600 条目的 README 和一个 161MB 的词库数据目录，把散落的中文 NLP 工具与语料第一次系统地组织了起来。它的走红路径清晰：起步于中文 NLP 资源稀缺期、依托知乎社区导流、以"几乎最全"的收录广度满足工程与科研两类人群的检索刚需。2023 年后维护停滞使其对 LLM 时代新方向的覆盖迅速过时，链接腐化与许可缺失的问题也会随时间放大；但其传统 NLP 部分的词库数据（人名、公司名、成语、敏感词、领域词库）至今仍被大量工程直接引用，索引本身也仍是了解"中文 NLP 有哪些轮子"的最佳速查表之一。适合 NLP 初学者按图索骥找工具与语料、工程团队快速取用基础词库；不适合作为 LLM 前沿资源来源，且任何数据商用前应回到各原始仓库确认授权。读到今天，它更像一座保存完好但不再上新的中文 NLP 图书馆——查旧籍极有价值，追新书需另寻门户。
