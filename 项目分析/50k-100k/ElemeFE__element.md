## 2. 项目是什么，解决什么问题

Element UI 为 Vue 2 应用提供一整套开箱即用的桌面端组件：从 Button、Input 等基础控件，到 Table、Date-Picker、Cascader、Tree、Transfer 等复杂交互组件，再到 Message、Notification、MessageBox 三类全局反馈组件，共 89 个组件（`packages/` 下 90 个目录 = 89 组件 + theme-chalk 主题）。README 自述为 "A Vue.js 2.0 UI Toolkit for Web"，并明确 "Element will stay with Vue 2.x"，Vue 3 用户被引导至社区接棒项目 Element Plus（`src/README.md`）。

它解决的核心问题是"中后台系统 UI 的标准化"：统一的设计语言（theme-chalk 主题）、统一的表单校验（内置 async-validator 封装于 Form 组件）、统一的全局反馈 API（`this.$message`、`this.$confirm` 等挂到 Vue 原型，见 `src/index.js` 的 install 函数），让业务团队无需自研组件即可快速搭建管理后台。这也是它 2016 年发布后迅速成为国内 Vue 生态事实标准的原因——配套四语文档站、可在线定制的主题、以及 `make new <组件名>` 的组件脚手架（`Makefile`），把"用"和"贡献"两条路径都做顺了。

工程上它的关键取舍是"组件即独立包"：每个组件在 `packages/<name>/` 下自成一体，通过 `components.json` 登记入口（`components.json`），既支持全量引入 `Vue.use(Element)`，也支持按组件引入配合 babel-plugin-component 做按需加载，CSS 也可按组件拆分（详见第 5 节）。

国际化深度内建：`src/locale/` 内置 60 种语言包（`src/locale/lang/` 计数），组件文案统一走 `t()` 函数，且能与 vue-i18n 互操作（`src/locale/index.js` 中检测 `$t` 后委托给 vue-i18n）。文档站本身也是四语（中/英/西/法），README 中以社区翻译团队署名（`src/README.md`）。

## 3. 技术栈与依赖

- **运行时**：Vue 2（peerDependency `^2.5.17`，`package.json`）；运行时依赖仅 6 个，全部为小工具库——`async-validator`（表单校验）、`deepmerge`（配置合并）、`normalize-wheel`（滚轮事件标准化）、`resize-observer-polyfill`（尺寸监听，兼容 IE）、`throttle-debounce`（节流防抖）、`babel-helper-vue-jsx-merge-props`（JSX 属性合并，`package.json` dependencies）。
- **第三方代码内嵌**：popper.js（Federico Zivolo，MIT）整个内嵌进 `src/utils/popper.js`，配合 `src/utils/vue-popper.js` 实现所有浮层（Tooltip/Popover/Select 下拉等）定位，不作为 npm 依赖。
- **构建链**：webpack 4 + babel 6（`babel-preset-env` + `stage-2` + vue-jsx）+ vue-loader 15；主题用 gulp 4（`gulp-sass` + `gulp-autoprefixer` + `gulp-cssmin`，`packages/theme-chalk/gulpfile.js`）；`node-sass` 编译 SCSS。
- **测试链**：karma 4 + mocha + chai + sinon（karma-sinon-chai），ChromeHeadless，istanbul 覆盖率 + coveralls（`package.json` devDependencies）。
- **文档站**：examples/ 下自建 Vue 2 单页文档，markdown-it 渲染示例（`build/md-loader/`），Algolia 做站内搜索（devDependencies 中 `algoliasearch`）。
- **兼容性目标**：README 明确支持 "Modern browsers and Internet Explorer 10+"，这也是代码中大量 polyfill（resize-observer-polyfill、es6-promise）与 babel 6 转译存在的理由（`src/README.md` Browser Support 一节）。

## 4. 目录结构与代码组织

| 目录 | 职责 |
| --- | --- |
| `packages/` | 90 个子包：89 个组件 + `theme-chalk` 主题；每个组件一个目录（`index.js` 入口 + `src/` 实现） |
| `src/` | 被组件共享的运行时代码：`index.js`（自动生成的主入口）、`locale/`（i18n）、`mixins/`、`directives/`、`transitions/`、`utils/`（popper、popup 管理、日期、DOM 工具等） |
| `build/` | 构建脚本：`webpack.*.js` 五套配置 + `bin/` 十个脚本（生成入口、i18n、版本、脚手架）+ `md-loader/`（文档渲染） |
| `types/` | 91 个 `.d.ts`，为每个组件提供 TypeScript 声明 |
| `examples/` | 文档站源码：264 个示例 markdown（`examples/docs/` 计数）、playground（`examples/play/`）、浏览器扩展（`examples/extension/`） |
| `test/` | `unit/`（karma 单测 63 个 spec）+ `ssr/`（SSR require 冒烟测试） |
| `.github/` | 四语 CONTRIBUTING、issue/PR 模板、stale bot 配置、PR 预览站 workflow |

组织方式评述：这是典型的"多包式组件库"但不是 monorepo——组件之间物理隔离（`packages/table/` 19 个文件是最大组件），共享逻辑下沉到 `src/`；入口文件 `src/index.js` 头部注明 "Automatically generated by './build/bin/build-entry.js'"，即组件清单的唯一事实来源是 `components.json`，入口、按需构建、类型声明都由它派生。新增组件用 `make new <name>` 脚手架一键生成骨架（`Makefile`、`build/bin/new.js`）。`src/` 与 `packages/` 双层结构配合 webpack alias（`element-ui/src/...`）保证组件内引用共享代码的路径在任何构建方式下都成立。

## 5. 核心架构与关键实现

### 5.1 组件标准封装与主入口生成

每个组件遵循同一模板：`packages/<name>/index.js` 只做 install 包装，实现放 `src/`。以 Button 为例（`packages/button/index.js`，全文 8 行）：

```js
import ElButton from './src/button';
ElButton.install = function(Vue) {
  Vue.component(ElButton.name, ElButton);
};
export default ElButton;
```

`build/bin/build-entry.js` 读取 `components.json`，用 `json-templater` 渲染生成 `src/index.js`：全量 install 时逐个 `Vue.component` 注册，另将 InfiniteScroll 指令、Loading 指令、以及 `$message/$msgbox/$notify/$loading/$confirm/$prompt` 挂上 Vue 原型（`src/index.js:183-207`），并写入全局默认配置 `Vue.prototype.$ELEMENT = { size, zIndex }`。这个 install 设计是 Vue 2 插件范式的标准实现，也是全库"命令式 API + 声明式组件"双轨的支点。

### 5.2 按需加载：多入口构建

`build/webpack.component.js` 把 `components.json` 的每个键作为 webpack 多入口，产出 `lib/<name>.js`（commonjs2，不压缩），加上 `build:utils` 把 `src/` 用 babel 转译到 `lib/`，使得 `import { Button } from 'element-ui'` 或 babel-plugin-component 的 `import { Button } from 'element-ui/lib/button'` 都能命中单组件文件，CSS 由 theme-chalk 按组件同名拆分（`packages/theme-chalk/src/` 下 96 个 scss 文件与组件一一对应）。这是 2018-2022 年间国内"element 按需引入"工程方案的事实标准配置。

### 5.3 Table 的内建 store（最重组件）

Table 是全库最复杂的组件（19 个文件），没有用 Vuex，而是为每个表实例建一个迷你 store：`packages/table/src/store/` 下 `watcher.js` 定义 Watcher（持有 states），`index.js` 以 mutations 对象组织状态变更。注释里明确解释了为什么不用 computed（`packages/table/src/store/index.js:8-10`）：

```js
// 没有使用 computed，而是手动更新部分数据
// https://github.com/vuejs/vue/issues/6660#issuecomment-331417140
this.updateCurrentRowData();
this.updateExpandRows();
```

即围绕 Vue 2 大数据量场景的手动精准更新：`setData` 时按需执行 updateSelection/updateAllSelected/updateTableScrollY 等步骤，避免整表重渲染。排序/筛选/树形展开分别是 `watcher.js`、`store/tree.js`、`store/expand.js` 的职责，表体/表头/表尾拆为 `table-body.js`/`table-header.js`/`table-footer.js` 三个渲染函数组件，用 `layout-observer.js` 订阅列宽变化。

### 5.4 浮层与弹层管理

所有浮层组件共享三层基础设施：内嵌的 popper.js 负责定位（`src/utils/popper.js`）；`src/utils/vue-popper.js` 封装成 Vue mixin；`src/utils/popup/index.js` 提供 popup mixin，管理 `visible`、modal 遮罩、zIndex 自增（`PopupManager`）、打开延迟与滚动条宽度补偿。`src/utils/clickoutside.js` 是全局点击外部关闭指令。message/notification/message-box 三个命令式组件则通过 PopupManager 统一调度 z-index，避免互相遮盖。

### 5.5 跨组件通信与国际化

`src/mixins/emitter.js` 提供 `dispatch`（沿 $parent 链向上找指定 componentName 派发事件）和 `broadcast`（沿 $children 树递归广播），是 el-form 与 el-form-item、el-menu 与 el-menu-item 等父子联动的基础。i18n 在 `src/locale/index.js` 实现：默认 zh-CN，`t()` 按点路径取词，若宿主应用已装 vue-i18n 则自动委托其 `$t` 并用 deepmerge 合并词表（`src/locale/index.js:8-24`）。

## 6. 构建与运行

以下命令均来自 `package.json` scripts 与 `Makefile`：

```bash
npm install                 # 或 make install
npm run dev                 # 启动文档站开发服务（webpack-dev-server, build/webpack.demo.js）
npm run dev:play            # 只启动组件 playground
make new button 按钮        # 生成新组件脚手架（build/bin/new.js）
npm run build:file          # 生成入口/图标索引/i18n/版本文件（build/bin/*.js）
npm run build:theme         # gulp 编译 theme-chalk 并拷贝到 lib/theme-chalk
npm run dist                # 完整发布构建：clean → build:file → lint → 三套 webpack → utils → umd → theme
npm run pub                 # 发布 npm（build/release.sh + 生成 Algolia 索引）
npm test                    # lint + build:theme + karma 单测单次运行
```

npm run dist 的产物形态由三套 webpack 配置分工：`webpack.common.js` 产出全量 commonjs 入口（`lib/element-ui.common.js`，package.json main 字段指向它）、`webpack.conf.js` 产出浏览器直连的 UMD 全量包（unpkg 字段指向 `lib/index.js`）、`webpack.component.js` 产出按需加载的单组件文件；`build:umd` 另单独生成多语言 locale 包（`build/bin/build-locale.js`）。

## 7. 测试与工程质量

- **单测**：`test/unit/specs/` 下 63 个 spec 文件、约 20800 行（wc 统计），karma + ChromeHeadless + mocha/chai/sinon，覆盖率 istanbul 上报 coveralls（`.travis.yml`、`test/unit/karma.conf.js`）。主要组件（table、date-picker、select、form 等）均有对应 spec。
- **SSR 冒烟**：`test/ssr/require.test.js`，仅验证服务端渲染环境下 require 主入口不报错，覆盖较浅。
- **CI**：Travis CI（node 10 + Chrome，跑测试并部署文档）；GitHub Actions `preview-build.yml`/`preview-deploy.yml` 为每个 PR 构建文档预览站（`.github/workflows/`）。
- **质量工具**：ESLint 4 + 自家 `eslint-config-elemefe`，lint 覆盖 src/test/packages/build；`src/mixins/migrating.js` 在组件内实现"弃用属性运行时告警"，是库内自洽的迁移提示机制。
- **观察**：依赖锁死在 webpack 4/babel 6/node-sass 时代的版本（`yarn.lock` 413KB），`node-sass` 与现代 Node 不兼容，今日复现构建需旧环境——这是维护停止后的典型冻结状态。

## 8. 社区与维护状态

- **活跃度**：创建于 2016-09，巅峰期为 2018-2021；最终 release v2.15.14 发布于 2023-08-24（`CHANGELOG.zh-CN.md`、GitHub API），最后一次推送为 2024-08-20（默认分支 dev，GitHub API），此后无提交。GitHub 上仓库未打 Archived 标记，但实质已停止维护。
- **背景**：Vue 2 于 2023-12-31 EOL，官方 README 早已声明 "Element will stay with Vue 2.x" 并把 Vue 3 用户导向社区项目 Element Plus（`src/README.md:41-43`）。任务简介中"2023 起归档/停止维护"与事实相符（停止维护属实，"归档"指状态而非 GitHub Archived 标记，未确认仓库方是否有正式公告）。
- **社区规模**：fork 14365、watch 1283、open issues 2967（GitHub API）；贡献者列表单页即满 100 人（`gh api contributors?anon=true` 返回 100，实际总数更多，未确认精确值）。issue 模板四语、stale bot 常驻（`.github/stale.yml`），说明曾经 issue 量极大需要自动化治理。
- **发布节奏**：CHANGELOG 显示 2.x 系列长期以小版本滚动修复 bug 与文档，无明显 breaking change，符合"稳定库维护期"特征。
- **编辑器生态**：除 91 个 `.d.ts` 外，根目录 `web-types.json`（140KB）为 JetBrains 系 IDE 提供组件属性补全元数据；官方还维护 Atom/VSCode helper 插件（`src/README.md` Links 一节），IDE 支持的完备度在同期组件库中少见。

## 9. 亮点与风险

**亮点**

1. 组件清单单一事实源（`components.json`）驱动入口生成、按需构建、类型声明，全库自动化程度高（`build/bin/build-entry.js`、`build/webpack.component.js`）。
2. 运行时依赖仅 6 个小工具库，popper.js 直接内嵌，对宿主项目的依赖侵入极小（`package.json`）。
3. Table 自建迷你 store 以 mutations 手动精准更新，正面回应 Vue 2 大表格性能问题，注释中留有出处（`packages/table/src/store/index.js`）。
4. 60 语言包 + 与 vue-i18n 自动互操作，国际化在 2016 年代的开源 UI 库中属第一梯队（`src/locale/`）。
5. 工程闭环完整：组件脚手架（`make new`）、四语文档站、PR 预览站、单测覆盖率上报，是国产开源项目工程化早期的范本。

**风险与局限**

1. 已停止维护：Vue 2 本身 EOL，不再有任何安全补丁，新项目不应选用（GitHub API、`src/README.md`）。
2. 技术栈冻结在 webpack 4/babel 6/node-sass，无法在现代 Node 环境直接从源码构建，二次开发成本高（`package.json`、`yarn.lock`）。
3. open issues 近 3000 无清理，社区答疑渠道（Gitter、钉钉群）活跃度未确认。
4. 深度绑定 Vue 2 的 Options API 与原型挂载模式，无法平滑迁移到 Vue 3；迁移只能走 Element Plus 的重写方案。

## 10. 总结评价

Element UI 是中文开源 UI 组件库的分水岭作品：它用极小的运行时依赖、清单驱动的构建体系和覆盖中后台全场景的 89 个组件，把"组件库"做成了基础设施，54k 星与国内 Vue 2 项目的普及率互相印证；它停更不是因为做得不好，而是它服务的 Vue 2 时代结束了，接棒者 Element Plus 是社区在同一设计语言上的 Vue 3 重写。今天读它的源码仍有三重价值：组件库工程化（清单驱动多入口构建、脚手架、文档站一体化）的经典范式；Vue 2 时代性能优化手法（Table 手动 store、popper 内嵌、clickoutside 指令）；以及一个开源项目从辉煌到退役的完整样本。适合维护存量 Vue 2 项目的工程师（了解其构建与按需加载原理）和想自己造组件库的人（借鉴其工程结构）阅读；新项目请直接使用 Element Plus。
