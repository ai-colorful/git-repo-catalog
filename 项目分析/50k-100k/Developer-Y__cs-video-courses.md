## 2. 项目是什么，解决什么问题

这是一个典型的 awesome 系内容仓库，仓库本体就是一份 Markdown 清单。它收录的是"有视频讲座"的大学水平 CS 课程：MIT OCW、Stanford、CMU、Berkeley、ETH、TUM、IIT（印度 NPTEL）、UNSW 等几十所高校的公开课视频链接（出处：`README.md` 全文）。

它解决的问题在 `NOTES.md` 中说得很直白：

1. **做在线书签/速查表，而不是教程**。作者刻意保持清单精简——"浏览 15 页的清单、找到课程开始学，比读 60 页的文字容易得多"（`NOTES.md` 第 3 行）。
2. **拒绝冗余描述**。作者认为同类课程（数据结构/OS/ML/网络等）课程大纲 80-90% 重叠，逐课写描述只会重复和主观化。取而代之，把课程号、课程名、年份、教授、学校直接压进链接标题里（`NOTES.md` 第 4-5 行）。
3. **直连视频，不要注册墙**。`CONTRIBUTING.md` 明确收录哲学："链接应直接指向可观看/下载的视频，而不是注册并等待下一期开课——这是视频课程清单，不是 MOOC 清单"（第 4 行）。

与同类清单 `awesome-courses` 的差异在于：本仓库只收"确实能点开就看"的视频课，且按大学课程编号组织，天然带难度层级和先修关系；`NOTES.md` 还给出 MIT/Stanford/UMN 的先修课图表链接，帮助学习者排课（第 7-11 行）。

## 3. 技术栈与依赖

没有任何运行时代码与第三方依赖（出处：tarball 顶层仅 3 个 Markdown 文件，无 package.json/requirements.txt 等任何工程清单）：

- **内容格式**：纯 GitHub Flavored Markdown。标题做目录锚点，嵌套列表做分类，markdown 链接做条目。
- **"技术"仅指 Markdown 卫生**：`README.md` 用 `<!-- omit in toc -->` 控制目录生成（第 1-5 行），条目统一 `- [课号 - 课程名 - 学校](URL) ([Video Playlist](...))` 格式。
- **无 CI、无自动化、无 .github 目录**（tarball 顶层确认不存在），一切靠人工 PR。

这种"零依赖"恰恰是它可持续的原因：没有依赖会腐烂，唯一会腐烂的是外链本身（见第 9 章风险）。

## 5. 核心架构与关键实现（收录范围与组织方式）

作为内容仓库，"核心实现"就是它的分类体系与条目设计：

- **26 个一级分类覆盖整个 CS 本科+研究生课程谱系**（`README.md` 标题行 L69-1614）：入门 CS、数据结构与算法、系统（OS/分布式/实时）、数据库、软工、AI、ML（最大章，L410-860，含 13 个子类）、网络、CS 数学、Web、理论 CS 与程序语言、嵌入式、体系结构、安全、图形学、图像与视觉、计算物理、计算生物、量子计算、机器人与控制、计算金融、网络科学、区块链、杂项。
- **条目元数据内联**：`[COMP1511 - Programming Fundamentals - UNSW (Complete Course...)](URL) | [Video Playlist](URL)`（`README.md` L71）。课程号=难度定位，年份=内容新鲜度，教授名=口碑检索键。
- **多年份并存**：同一门课的不同学期版本并列收录。最典型的是 CMU 15-445 数据库课，一条目下挂了 2017-2025 共 9 个年份的 YouTube 播放列表（`README.md` L301）。
- **来源以 YouTube 播放列表为主干**（占全部外链约 54%，见第 7 章统计），辅以各校 OCW/课程主页/校内视频平台（Panopto、fau.tv、tele-task.de 等）。

## 9. 亮点与风险

亮点：

1. **收录哲学清晰且贯彻到底**：只收有视频、可直连、讲解完整的大学课，拒绝浅 MOOC（`CONTRIBUTING.md`），这让清单的信噪比远高于泛 awesome 列表。
2. **课程号即难度坐标**：以真实大学课程编号组织，配合 NOTES 里的先修课图表链接，天然是一张 CS 学习路线图。
3. **十年如一日的维护**：2016 年至今持续回填新课（2025/2026 年课程占比可观），84k 星是长尾积累而非一波热点。
4. **零依赖、零构建**：纯 Markdown 意味着永远不会因依赖腐烂而失效，10 年后依然可用。

风险/局限：

1. **无许可证**：仓库没有 LICENSE 文件（API license=null，顶层文件确认），严格来说他人不可合法再分发，这在 awesome 系仓库里少见。
2. **链接腐烂无自动化兜底**：1836 个外链中大量指向大学课程页（每学期换路径），且无 CI 链接检查；实测已存在坏链接，如 `README.md` L1546 的条目链接竟指回本仓库自身（`https://github.com/Developer-Y/cs-video-courses?tab=readme-ov-file`）。
3. **来源偏科**：英文世界 + 印度 NPTEL（106 链接）为主，中文资源几乎缺失（Bilibili 仅 2 处链接，L138、L620）。
4. **单文件 227KB 的维护税**：所有 PR 集中改动一个巨大 README，review 粒度粗，分类偶有不规范（如 "Real time system evaluation" 章节，L1167）。

## 10. 总结评价与生态位

cs-video-courses 是 awesome 系清单里的"长青款"：它赢在定位的克制（只要视频课、只要直连、不写废话）和执行的耐久（十年回填不辍），而不是任何技术含量。84k 星本质上是对"一张可扫读的全球 CS 公开课地图"这一刚需的投票。它在生态中与 prakhar89/awesome-courses（大而全的通用课表）、OSSU/computer-science（带学位结构的课程体系）互为补充：本仓库介于两者之间——比 awesome-courses 更聚焦视频与大学课，比 OSSU 更松散但更新更快（README L1682 的 Related 区仅互链了一个理论 CS 清单）。适合三类人：自学 CS 或转行者拿它排学习路径；在职工程师按课程号直取某领域的名校课；教育研究者用它观察哪些大学的公开课生态最开放。它不适合想找中文课程、想要学习监督/作业批改、或期待结构化学位路径的人。对想抄作业做清单类仓库的人，其 NOTES.md 里"元数据内联进链接标题、拒绝逐条描述"的设计决策值得直接借鉴。
