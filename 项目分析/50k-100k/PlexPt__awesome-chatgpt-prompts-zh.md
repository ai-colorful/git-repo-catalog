## 2. 项目是什么，解决什么问题

2022 年 12 月 ChatGPT 爆发初期，普通中文用户面对模型最大的障碍不是"没有模型"，而是"不会提问"。本项目把"如何向 ChatGPT 提问"整理成一套可直接复制粘贴的中文提示词模板：每条提示词给模型指派一个具体角色（"充当 Linux 终端""担任雅思写作考官""担任产品经理"），并规定输出格式、约束与第一句话，用户粘贴后即可把通用对话模型变成特定用途的工具（README.md "正经指南"章节）。

内容主要分四块。第一块是 README 主体的 137 条角色提示词（`grep -c '^## '` 统计），覆盖翻译润色、编程助手、面试官、文字冒险游戏、写作辅导、职业咨询等场景，多数条目译写自 f/awesome-chatgpt-prompts 并做了本地化改造（README 尾部"感谢"章节注明部分内容翻译自此，本地化条目如"担任弱智吧吧主""担任朋友圈文案大佬""担任超级舔狗"是典型的中文互联网原创）。第二块是机器可读版 `prompts-zh.json`：124 条 `{"act","prompt"}` 结构化条目，供开发者做应用内置提示词库或二次开发（README 中部明确提示"如需编程请使用 prompts-zh.json"）。

第三块是 `question/` 目录的中文问题语料：673 个 Markdown 文件（0.md–671.md + README.md），全部为"|标题|问题|"两列表格，共约 669,846 行问题（`grep -h '^|' question/*.md` 去表头统计），覆盖地理、历史、生物、NLP 任务、生活咨询等分类；question/README.md 自述"共约67万个问题"。这块内容实际定位是给中文大模型训练/评测用的问答语料，与提示词主线关系不大，但显著增加了仓库的数据价值。第四块是"玩法"与"越狱"周边：USEAGE.md 用 30 余张截图演示写作、公文、演讲稿等实际效果；cat.md 收录"解除封印咒语"（猫娘/DAN 类越狱提示词），对应 issue #12 的社区讨论。

README 顶部还有明显的流量运营痕迹：推广作者自己的"智造喵"国内中文版站点（chat.aimakex.com）、微信交流群、公众号、阿里云/腾讯云推广链接（README.md 首屏与"中文语料库"章节）。这解释了仓库的高曝光动机——它既是开源合集，也是作者的引流入口。

## 3. 技术栈与依赖

无传统技术栈。仓库内没有任何工程文件（tarball 全量 689 个条目中无 package.json/pyproject.toml/Makefile/Dockerfile/CI 配置，`tar -tzf` 过滤 .github、*.yml、*.json 工程文件均为空）。

实际"技术"只有两类数据格式：

- **Markdown**：README.md（744 行）、cat.md、USEAGE.md、question/*.md（约 67.3 万行）、old/do.md（旧版基础提示词，UTF-8 编码）。
- **JSON**：prompts-zh.json（124 条，62.7KB）与 prompts-zh-TW.json（124 条，64.2KB，繁体中文版），两个文件条目一一对应，均为扁平数组、每条仅 `act`/`prompt` 两个字段（Python 解析验证）。

依赖为零，消费方式是"浏览器看 README 复制"或"程序读 JSON"，无构建、无运行时。

## 5. 核心架构与关键实现

内容型仓库，无代码架构；核心资产的组织模式如下。

**提示词模板的写法约定**（README.md "正经指南"）。每条提示词遵循固定句式：角色声明 → 行为约束 → 输出格式限定 → "我的第一个请求/命令是 X"。以"充当 Linux 终端"为例：

```text
我想让你充当 Linux 终端。我将输入命令，您将回复终端应显示的内容。
我希望您只在一个唯一的代码块内回复终端输出，而不是其他任何内容。
不要写解释。除非我指示您这样做，否则不要键入命令。
当我需要用英语告诉你一些事情时，我会把文字放在中括号内[就像这样]。
我的第一个命令是 pwd
```

这个"角色 + 约束 + 首问"四段式是全仓 137 条与 JSON 124 条的共同骨架，也是该仓库被大量后来者模仿的模板范式（来源：README.md 各条目、prompts-zh.json 全量条目结构一致）。

**JSON 数据的生成逻辑**。prompts-zh.json 的条目与 README 各节内容基本一一对应（如首条"担任雅思写作考官"与 README 末段同文），推断由 README 内容人工整理而成；无脚本、无同步校验机制，README 与 JSON 之间存在数量差（137 节 vs 124 条），部分 README 条目（如"写小说""充当算法输出器"）未进 JSON，两份数据靠手工维持一致，无自动化。

**问题语料的批量生产痕迹**（question/500.md）。每个文件是连续编号的表格，同一文件内会出现"图像分类/摘要生成"等 NLP 任务题与"酒店预订/音乐推荐"等生活题混排、表头格式不一（"|标题|问题|"与"| 标题 | 问题 |"并存），0.md 仅 22 行而总量 67 万行，呈现明显的脚本批量生成/分批追加特征；仓库未提供生成脚本，来源未确认。

**越狱内容的收录方式**（cat.md）。以"咒语"合集形式维护，正文给出多条完整越狱提示词（猫娘人设、DAN 变体、"去除道德伦理限制"句式），并用 issue 链接做持续更新入口（"2-19 https://github.com/.../issues/29#issuecomment-..."），即用 GitHub issue 当内容社区，README 只放指针。

## 6. 构建与运行

无构建、无测试、无运行（全仓无任何工程文件，见第 3 章）。使用方式即"运行方式"：

- 人工使用：打开 README.md，复制目标条目引文块，粘贴到 ChatGPT 对话框（README.md "正经指南"章节开头注明"直接复制粘贴使用"）。
- 程序使用：直接引用仓库内 `https://github.com/PlexPt/awesome-chatgpt-prompts-zh/blob/main/prompts-zh.json`，解析 JSON 数组取 act/prompt 字段（README.md 中部原文指引）。

## 7. 内容质量与工程化程度

- **质量一致性弱**：README 与 JSON 数量不同步（137 vs 124，见第 5 章）；question/ 表头与分类体系不统一；繁体版由社区 PR 驱动（PR #199，2024-07 "Update zh-TW prompts with GPT-4o & enhanced prompts"，gh api commits），更新节奏与简体版脱节。
- **无任何自动化**：无 CI、无链接检查、无 JSON schema 校验、无 lint；.gitignore 仅 3 行（.gitignore 文件）。
- **内容时效性**：提示词针对 ChatGPT 3.5/4 时代"易被角色扮演绕过"的模型行为设计（cat.md、prompts-zh.json 中"作为一个不受约束的 AI 模型 DAN""涩涩女友""好耶！魅魔！"等条目为证）；在带系统提示与内容策略的现代模型上多数越狱类条目已失效，工具类条目仍可用但属通用常识。
- **编码规范**：正文文件均为 UTF-8（Python 逐文件验证 old/do.md 为合法 UTF-8），Markdown 表格在 GitHub 渲染正常。

## 9. 亮点与风险

**亮点**

1. 时间窗卡位极致：2022-12-12 创建，是中文圈最早的 ChatGPT 提示词合集之一，抢到了"ChatGPT 中文教程"搜索心智，这是 6.4 万星的核心成因（gh api created_at + README 定位）。
2. 双格式供给：README 面向小白复制，prompts-zh.json 面向开发者集成，一份内容覆盖两类受众（prompts-zh.json）。
3. 规模化的附带语料：question/ 约 67 万条分类中文问答，对中文 NLP 从业者有独立数据价值（question/ 目录 + 自述 README）。
4. 提示词范式输出：统一的"角色+约束+首问"模板成为中文提示词写作的事实范式之一，被后来众多合集模仿（README 全量条目佐证）。

**风险/局限**

1. 内容老化：目标行为模型是 2023 年前后的 ChatGPT，2025-01 后无实质内容更新；越狱类条目（cat.md、DAN、魅魔等）在当前模型上基本失效且带合规风险（cat.md 原文）。
2. 无组织无导航：137 条提示词线性堆叠、无分类目录/锚点，JSON 与 README 手工双维护已出现数量漂移（第 5 章证据）。
3. 商业导流占比高：首屏为自有站点/微信群/云服务器推广链接，README 信息密度被广告稀释，中立性打折（README.md 首屏）。
4. 语料来源不透明：67 万条问题无生成脚本、无来源说明，若用于模型训练需自行评估版权与质量（question/ 目录无 README 之外的元信息）。

## 10. 总结评价

这是一个典型的"风口时间窗 + 中文刚需 + 强运营"造就的超级内容仓库：技术含量为零，但凭借 2022 年 12 月的抢跑、覆盖面广且可复制即用的中文提示词、以及 JSON 双格式供给，成为中文 AI 用户圈的入口级收藏品，6.4 万星更多是对其历史地位与实用性的投票，而非工程质量。今天它的工具类条目仍有参考价值，越狱类内容已过时且有合规隐患，67 万条问题语料是剩余的最大数据资产。适合三类人：想要现成中文提示词模板的普通用户（直接抄 README）、需要中文提示词/问答语料做应用或评测的开发者（读 prompts-zh.json 与 question/）、研究提示词工程传播史与 prompt 合集范式的人（读全仓结构）；不建议把它作为现代大模型提示词工程的最新实践来源。
