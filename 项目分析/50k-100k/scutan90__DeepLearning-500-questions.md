## 2. 项目是什么，解决什么问题

这是 2018 年由谈继勇（scutan90，南方科技大学与哈工大联合培养博士、瀚维智能医疗技术总监，见 `README.md` 作者简介）发起的中文深度学习知识库，以"问题—图解—公式推导—结论"的问答体组织内容，定位是 AI 工程师笔试/面试的查漏补缺手册与面试官出题参考（`English version/README.md` 中的 How to Use 部分明确了这一使用方式）。仓库标题虽叫"500 问"，实际组织为章节树：每章一个大主题，章内按"节.小节"编号展开具体问题。

内容主线是"基础理论 → 经典网络 → 视觉应用 → 工程实践"：第 1-3 章打数学、机器学习、深度学习底子；第 4-7 章讲经典网络与 CNN/RNN/GAN；第 8-9 章是目标检测、图像分割两大视觉应用；第 10-16 章覆盖强化学习、迁移学习、网络搭建与训练、优化算法、超参数调整、GPU/框架选型和 NLP；第 17-19 章转向工程侧——模型压缩与移动端部署（含 NCNN 部署专文 `ch17_模型压缩、加速及移动端部署/17.8.1 NCNN部署.md`，985 行）、后端架构选型，甚至软件专利申请（`ch19_软件专利申请及权利保护/`）。这种从算法一路讲到部署与知识产权的跨度，在同类面试仓库中少见。

仓库有两条值得注意的"副产品"线索。其一，HEAD 上的 `README.md` 已整体替换为图书宣传页：内容经博文视点出版为《深度学习500问——AI工程师面试宝典》（京东售卖链接写在 README 首行），共 14 章，谈继勇主编、郭子钊/李剑/佃松宜副主编，编委含 CVer 创始人陈方杰（Amusi）、微软亚研王晋东等——开源仓库反哺出版是它的商业化路径。其二，`English version/` 目录是 2020 年 10 月由滑铁卢大学 Arjun Krishna 发起的英译工程（README 自述"Google Translate + 部分人工翻译"），但只完成前 4 章，`Translation Required` 文件持续挂着求译者启事。

内容型仓库的典型特征在这里很纯粹：全仓库没有一个业务代码工程，GitHub 主语言显示 JavaScript 只是因为文档站脚本 `docsify.js`（152KB，vendor 进仓库）是最大的"代码"文件（`index.html` 第 78 行引用）。

## 3. 技术栈与依赖

| 层 | 技术 | 用途与出处 |

无 package.json、无构建脚本、无 CI——部署方式就是 GitHub Pages 直接托管仓库根目录。

## 5. 内容组织与生产机制（核心模块分析）

**问答体条目结构**（以 `ch02_机器学习基础/第二章_机器学习基础.md` 为例）：章内 `## 2.14 线性判别分析（LDA）` 为节，`### 2.14.1 LDA思想总结` 为单问；标准答法是"一句话结论 + 图解（引用 `img/ch2/2.29/1.png`）+ 公式推导（LaTeX）+ 工程注意点"。全仓库 `###` 级条目共 599 个（`grep -c '^### '` 各章求和），与"500 问"品牌吻合。内容密度差异很大：第二章 2,456 行/111 问最厚，第八章目标检测 1,506 行/50 问；而第十六章 NLP 仅 101 行/3 问、第十章强化学习 129 行/3 问，基本是占位骨架——"完成度随认领人投入浮动"是该仓库最真实的生态。

**章节认领制**：每个 `readme.md` 是一页认领台账，模板固定为"负责人 + 贡献者（排名不分先后）"，署名格式"学校/公司-职位-姓名"（如 `ch18_后端架构选型及应用场景/readme.md` 的"中国平安-AI系统研究员-梁志成"）。许多章节的负责人栏仍是 `xxx研究生-xxx（xxx）` 占位符（`ch02_机器学习基础/readme.md`），说明认领机制在后期实际运转有限。

**修改日志**：`modify_log.txt` 逐条记录署名日期的改动（`ch01_数学基础/modify_log.txt` 首条为 shw2018 2018-10-25"新增章节markdown文件"，并定下 img/readme/modify_log/正文四件套的目录约定）。这是没有 git 历史阅读习惯的社区协作者之间的土法 CHANGELOG。

**文档站渲染管线**（`index.html`）：docsify 单页 + `loadSidebar: true` 全局侧边栏；有个针对 docsify 路径 bug 的补丁钩子（L48-52，把 `../img` 重写为 `img`）；公式走"KaTeX 先渲染 + MathJax Typeset 兜底"双轨（L38 与 L56）。这套配置 2018-2019 年在中文技术文档仓库中是标准范本。

**章节内容梯度**：视觉主线（ch02/ch03/ch08/ch17）是重投入区，尾部章节（ch10/ch16）和英译版是薄区；两版 ch18 并存、侧边栏章号错排（`_sidebar.md` L19-20 两条"第十八章"）等痕迹表明 2021 年后的整理并未收尾。

## 6. 阅读与本地使用

无构建/测试。三种用法（出处：`English version/README.md` How to Use、`index.html`）：

- GitHub Pages 在线阅读：仓库默认页即 docsify 站点（`.nojekyll` 存在即为此目的）
- 本地起站：任意静态服务器指向仓库根目录即可（docsify 是纯前端 SPA），如 `python -m http.server` 或 `npx docsify-cli serve`；编辑器推荐 Typora（英文版 README 明确推荐 https://typora.io/）
- 直接读源文件：各章 md 自包含，配合对应 `img/ch{n}/` 目录在任何 Markdown 阅读器可用

## 7. 内容规模与质量

- 规模：53 个 Markdown 共 23,529 行（`wc -l` 汇总），其中中文章节正文约 1.7 万行；1,134 张图片；`###` 级问答条目 599 个（tarball HEAD 统计）
- 质量观察：第二章等核心章有完整公式推导（含 Fisher 信息矩阵、自然梯度等进阶内容，`ch02_.../第二章_机器学习基础.md` 2.13 节）和成套图解，达到入门教材水准；但全仓库无参考文献严格校对、无自动化检查，配图风格不统一，尾部章节明显单薄
- 结构一致性：好于一般 awesome 清单——有统一的条目编号、目录三件套约定，但存在已知的编号残留问题（两个"第十八章"，`_sidebar.md` L19-20）
- GPL-3.0 用于内容仓库偏"重"（更适合代码），英文版 README 还特别声明了禁止盗版搬运

## 9. 亮点与风险

亮点：

1. 中文深度学习面试资料的早期定义者之一，问答体 + 图解 + 公式推导的条目范式后来被大量仿写（1,134 张自制配图是实打实的投入）
2. 章节认领制 + readme 台账 + modify_log 的协作设计，让 100+ 贡献者、500+ PR 的社区生产在无 CI、无审校工具下仍保持了基本结构一致
3. 知识跨度完整：数学 → 模型 → 视觉应用 → 压缩部署 → 后端架构 → 专利保护，一条龙覆盖面试全链路
4. 开源→出版闭环：5.7 万星直接转化为博文视点图书，是中文技术开源社区"流量变现"的标杆案例
5. 开箱即用的 docsify 站点，零构建成本，GitHub Pages 托管即可全文检索阅读

风险/局限：

1. 内容停滞于 2021-10（主分支口径），缺少 Transformer 细讲、扩散模型、大语言模型等 2022 后主线内容，作为面试资料已明显过时
2. 章节完成度极不均衡：ch02 111 问 vs ch16/ch10 各 3 问；两版 ch18 并存、sidebar 章号错排等未清理
3. 无审校与引用体系，公式与表述的准确性依赖认领人水平，仅适合作为面试复习索引而非唯一学习来源
4. GPL-3.0 对"转载聚合站"约束力有限，英文版 README 自述需要防盗版——内容被大量镜像搬运不可控（未确认具体数量）

## 10. 总结评价

这是"2018-2021 中文 AI 求职潮"的活化石：一套组织松散但体量扎实的问答知识库，靠章节认领的众包模式聚合了 100+ 贡献者，以 5.7 万星成为中文深度学习面试资料的头部品牌，并成功出版为纸质书。它的工程含量近乎为零（一个 vendor 的 docsify 站点就是全部"代码"），价值完全在内容结构与社区生产机制上——问答体条目范式、认领台账、土法修改日志，都是内容型仓库协作的典型样本。今天它更适合两类人：正在准备传统 CV/ML 面试、需要快速查漏补缺的求职者（重点读 ch02/ch03/ch08/ch17），以及研究"GitHub 星标内容仓库如何运营与商业化"的社区观察者。当代学习者应警惕其知识截止线——它不覆盖大模型时代，且主分支五年未更新，阅读时需自行叠加新文献。
