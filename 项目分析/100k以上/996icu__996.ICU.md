## 2. 项目是什么，解决什么问题

996 工作制指"早 9 点到晚 9 点、每周 6 天"的非官方加班制度（`README.md` "What is 996?" 一节）。2019 年 3 月 26 日，一名中国程序员 @996icu 在 GitHub 创建此仓库，3 天收获 10 万+ 星（`ANTI-996 DAY.MD` 中自述），并迅速被 Financial Times、Wired、RadiiChina 等外媒报道（`README.md` 相关报道一节）。仓库名 996.ICU 的含义是：按 996 模式工作，迟早进 ICU（重症监护室）。

仓库要解决的问题不是技术问题，而是**信息不对称与集体沉默**：它把分散在知乎、看准网、脉脉、Boss 直聘等平台的违法加班证据，聚合成一张可检索、可引用、可长期归档的黑名单（`blacklist/README.md`）；反向维护一张 965 良好工作制公司白名单（`whitelist/README.md`）；并创造性地用开源许可证作为武器——Anti-996 License 在 MIT 文本上附加"使用者必须遵守其所在地劳动法律法规"的条件（`LICENSE` 第 17-38 行），试图让违反劳动法的公司"用不了"遵守该许可证的软件。

行动路径在 `README_CN.md` "我能做什么"一节写得非常具体：带证据提交黑名单 PR、给项目挂 996.icu 徽章（`externals/instruction.md`）、采用反 996 许可证、提交发展议案（`proposal/`）、参与"互助式举报"（`externals/mutual_help.md`——两位不同公司的受害者互相以朋友身份向对方所在地劳动监察大队举报，规避实名报复风险）、甚至直接向国务院"互联网+督查"平台反映。仓库明确声明"这不是一个政治运动，我们坚定维护劳动法"（`README.md` Principles and purposes 一节）。

该仓库是 GitHub 历史上星数最高的仓库之一，其意义早已超出内容本身：它是"用开源社区的组织方式做劳工权益倡导"的标志性案例，也把"反 996 许可证"的讨论带进了 OSI、开源合规和法律界的视野。

需要澄清的一个常见误解：本仓库**不是** 996.icu 网站的源码。网站是独立项目，本仓库只承载名单、许可证与翻译内容（`README.md` 顶部链接跳转即可见）；仓库名中的 ".ICU" 与内容中的徽章、许可证构成完整的品牌体系，且 README 特别声明"除官方域名和本仓库外没有任何官方账号、app 或周边"（`README.md` 开头加粗警告），以防范借运动名义的仿冒。

## 3. 技术栈与依赖

这是典型的**内容型/社会运动型仓库**，没有产品代码：

- 主体为 Markdown 文档（全仓 70 个 .md，文件类型统计自 tarball），网站 https://996.icu 为独立仓库，不在本仓库内（`README.md` 仅以链接形式引用）。
- 唯一的"代码"集中在 `archived/licenses[WIP]/tools/` 下三个社区贡献的许可证生成器 CLI（均已归档、停止维护）：
  - `gen-license-go/`：Go + cobra 风格 CLI，作者 panjf2000，含预编译产物（`bin/windows/gen-license-go.exe` 约 4MB、osx/linux 二进制），`go.mod`/`go.sum` 齐全；
  - `gen-license-rs/`：Rust + clap 2.32（`Cargo.toml`，edition 2018），内置 13 种许可证文本（含 `996icu-0.1`）用 `include_str!` 编译进二进制；
  - `gen-license/`：Python setuptools 包 v0.0.2（`setup.py`，console_scripts 入口），外加一个 Sphinx 风格 Makefile；
  - `test-gen-license/`：Rust 写的对上述 Go/Python 工具的验收测试骨架（`src/test_go.rs`、`src/test_py.rs`，`test_rust.rs` 为空文件）。
- 无 CI 配置、无 package.json/go.mod 位于顶层、无测试框架——符合"文档即仓库"的定位。`.gitattributes` 仅设 `* linguist-detectable=false`（刻意让 GitHub 语言统计显示为空）。

## 5. 核心架构与关键实现

内容仓库无软件架构，以下是其"内容架构"的四个核心机制：

**(1) 黑名单的证据标准与格式**（`blacklist/README.md`）。表头为"所在城市｜公司名字｜曝光/施行时间｜制度描述｜证据内容"，当前主表 235 条记录、另有"已取消 996 名单列表"6 条。贡献指南要求外部证据（官方公告/招聘页面）或内部证据（邮件/打卡/群聊截图），并明确"证据链接将自动提交 Internet Archive 归档"、提醒抹除个人信息、防数字盲水印建议屏摄。制度描述覆盖 996/995/大小周/11116/007 等各档（主表最新条目：2025 年 1 月杭州彩讯股份、2025 年 3 月北京安华金和天津研发中心）。

**(2) Anti-996 License 的法律设计**（`LICENSE`）。全文 47 行，MIT 授权条款保留，核心新增第 2、3 条：使用者须"严格遵守其所在地或注册地的劳动法律法规（以更严格者为准）"，且不得诱导/强迫员工放弃劳动法权利。这是全仓库传播最广的"代码"，GitHub License API 对其返回 NOASSERTION（未被 SPDX 收录）。

**(3) 多语言传播层**（`i18n/`）。36 个翻译文件把主文档的含义（"996 违反宪法与劳动法"的条文论证见 `i18n/en_US.md` Laws and Regulations 一节）推向全球，文言文与克林贡语版本体现了社区的自发热情。

**(4) 归档的许可证生成工具链**（`archived/licenses[WIP]/tools/gen-license-rs/src/main.rs`），用于一键生成"主流许可证 + 996ICU 附录"的 LICENSE 文件：

```rust
let all_licenses: HashMap<&'static str, &'static str> = {
     let mut ans = HashMap::new();
     ans.insert("agpl-3.0", include_str!("licenses/agpl-3.0.txt"));
     ans.insert("apache-2.0", include_str!("licenses/apache-2.0.txt"));
     ans.insert("mit", include_str!("licenses/mit.txt"));
     ans.insert("996icu-0.1", include_str!("licenses/996icu-0.1.txt"));
     ans
};
// usage: gen-license-rs mit --996icu en-us
```

另有 `LICENSE-MIT-996`、`LICENSE_Apache_no_overtime` 等变体草案（`archived/licenses[WIP]/README.md`），显示许可证迭代曾并行探索多条路线，后整体归档。

## 6. 构建与运行

本仓库无构建、无测试、无运行时。可直接进行的操作：

- 阅读/贡献内容：直接编辑各名单 `README.md` 并提 PR（唯一"发布"方式）。
- 挂徽章（`externals/instruction.md`）：在项目 README 加一行
  `[![996.icu](https://img.shields.io/badge/link-996.icu-red.svg)](https://996.icu)`
- 归档工具如需试运行（未经本分析验证，静态阅读结论）：
  - Rust 版：`cd "archived/licenses[WIP]/tools/gen-license-rs" && cargo build`（clap 2.32，edition 2018）
  - Go 版：`cd "archived/licenses[WIP]/tools/gen-license-go" && go build`，或直接用 `bin/` 下预编译二进制
  - Python 版：`python setup.py install`（无第三方依赖，`REQUIRE = []`）

## 7. 收录范围、分类体系与条目规模

- **黑名单**（`blacklist/README.md`）：收录标准锚定《劳动法》第 41/43/44 条与《刑法修正案（八）》第 41 条（文件开篇脚注），限定"违法加班"而非"一切加班"；235 条在榜 + 6 条已取消，证据以截图链接为主、图片入库为辅；另有针对不熟悉 GitHub 劳动者的第三方提交通道（`README_CN.md` 引用 996action.com）。
- **白名单**（`whitelist/README.md`）：仅 10 条，均为 2019 年 4-5 月录入的 965/弹性工作制公司（含 IBM），此后几乎停止更新——白/黑名单的不对称增长本身就是观察结果。
- **awesomelist**（`awesomelist/README.md`）：165 个采用 Anti-996 License 的项目，含野火 IM server、WxJava、Yearning 等一度知名的项目。
- **i18n**：36 个语言版本。
- **分类体系**：黑名单不按行业/规模分类，仅按城市列；remotelist 按城市拼音分目录但基本为空模板。
- **条目质量分层明显**：早期条目多为"领导口头描述"这类弱证据（如 `blacklist/README.md` 上海百安居一行），后期条目普遍附群聊截图、OA 打卡记录、内部邮件（如 2023 年北京信安世纪一条附内部邮件与 OA 打卡两个外链），证据规范在社区实践中逐步收紧。
- **黑名单条目示例**（均出自 `blacklist/README.md`，体现覆盖广度）：拼多多（11116、两班倒，2019-02）、字节跳动（996，2017-07）、京东（995，2019-03）、58 同城（996，2019-04）、美的集团（996 大小周）、云南联通新通信（996，2020-02 起）、广东数果科技（钉钉打卡设 21:00 才算下班，2021-08）等；行业横跨电商、物流、金融、游戏、律所（金杜律师事务所 2019-04 在列）。
- **已取消名单**（`blacklist/README.md`"已取消996名单列表"）记录了 6 条被撤销的条目及撤销原因（如"没有任何证据""被无故取消"），这一自我纠错记录在同类众包名单中少见，是名单公信力机制的组成部分。

## 8. 更新机制与社区治理

- **更新机制**：纯人工 PR 流程，无任何自动化（无 CI、无机器人、无脚本，目录中不存在 .github/）。维护者人工筛选符合证据标准的 PR 后展示；争议条目走"提 PR 说明情况，核实后更正或删除"的申诉路径（`blacklist/README.md` 声明一节）。
- **活跃度**：仓库仍在低频更新——gh api `pushed_at` 为 2025-08-22，黑名单 2025 年新增 2 条；但相比 2019 年的爆发期（3 天 10 万星），近年的更新主要是零星名单维护。
- **治理特点**：Issues 被维护者主动关闭（`README.md` 明言"Issues 区完全失去控制……我个人决定关闭"）；开放议题转入 Slack 频道与 PR；17,000+ 个未合并/未关闭的 PR 堆积在仓库（gh api open_issues_count 含 PR 为 16,689），显示单人维护模式已难消化社区洪流。约 396 名贡献者，无 release、无版本管理，符合宣言式仓库的治理形态。
- **风险应对迹象**：`README_CN.md` 顶部置顶了一条 2023 年承德程序员案的声援声明，说明维护者仍会就行业热点表态；黑名单页脚注引用劳动法条文、`externals/official.md` 以"无"记录官方表态，都属于运动型仓库特有的"证据姿态"管理。

## 9. 生态位与姊妹项目

`README.md` "Community powers" 一节官方收录的衍生项目：955.WLB（955 公司白名单，formulahendry）、996.LIST（匿名投票榜）、996.Leave（海外就业）、996.Petition（公开信请愿）、996.avengers/Natasha（在招聘网站打标）、996.OD（职业病）、996.Blockchain（证据上链）、996.Error（各语言 996 异常库）、699cn（微信一键存证小程序）等十余个，形成"曝光—存证—求职避险—维权"的松散生态。生态位上，996.ICU 是这一波运动的母仓库与符号源头；媒体层面（FT、Wired、新华社《996当退场》、人社部与最高法超时加班典型案例，见 `README.md`/`README_CN.md`），它成为公共讨论的锚点；法律层面，Anti-996 License 引发了国际开源界对其是否合规的长期争论（本仓库内可见的证据是 GitHub License API 的 NOASSERTION 与 `proposal_to_request_github_official_including_996icu_license.md` 的诉求）。

## 10. 为什么能涨到 27.7 万星 —— 总结评价

涨星逻辑与代码仓库完全不同：**它是情绪、时机与行动成本的乘积**。2019 年 3 月 996 议题积怨已久又恰逢资本家言论争议（马云"福报"说被收录在 `README.md`），996.ICU 提供了一个零门槛的表态动作——点一下 star 即是抗议，挂一枚徽章即是站队；外媒与 Python 之父的背书（Guido："996 工作制是不人道的"，`README.md`）又把它推成全球新闻事件。Star 在这里的功能更接近签名而非收藏，因此它成为 GitHub 历史上星数最多的仓库之一。

总评：这不是一个软件项目，而是一场以 Git 为载体的社会运动档案库——一张仍在生长的违法加班黑名单、一份有法律野心的许可证草案、一本 36 种语言的宣言。它的历史价值（记录 2019 年以来中国互联网加班生态的一手证据）大于工程价值；它的问题也很典型：145MB 图片把仓库撑到 160MB、PR 洪流无人消化、白名单与工具链均已停摆、许可证至今未被 SPDX/OSI 接受。适合三类人：研究平台治理与数字社会运动的观察者；想了解 Anti-996 License 条文与合规争议的法务/开源合规从业者；以及想为黑名单补证据、维护继续生长的中文开发者。若要读"源码"，直接读 `blacklist/README.md`、`LICENSE` 与 `externals/mutual_help.md` 这三个文件，就读完了这个项目的全部精髓。
